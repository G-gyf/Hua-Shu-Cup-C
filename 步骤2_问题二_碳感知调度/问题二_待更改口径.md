# 问题二待更改口径

> 状态：待实施。本文只锁定后续模型、结果表和论文表述需要调整的口径，不改动已产出的运行结果。

## 1. 基准方案口径

| 项目 | 现行口径 | 拟改口径 |
|---|---|---|
| 原始源区域到达即启动方案 | 同时作为业务对照和早期 ε 参考 | 仅作为业务对照，明确标注 GPU 峰值超容量 358.8 张卡、不可行，不参与优化比较、ε 定义或 Pareto 筛选 |
| 可行基准 | 容量可行方案用于部分增量指标 | 统一使用“满足全部硬约束的零碳服务基准”计算增量成本、REU、等待和时延；原始对照只保留 `*_vs_SourceImmediate_*` 展示字段 |

## 2. 碳排放口径

### 需要取消的口径

不再使用“在 `[C_min, C_base]` 内均匀取四档碳预算”的 ε 轴。当前运行已证明：

```text
C_base = 0 tCO2
C_min  = 0 tCO2
```

四档碳预算完全相同，不能形成成本—碳排 Pareto 前沿。

### 拟采用口径

将零购电/零碳排设为所有最终方案的硬约束：

```text
GridPurchase_rt = 0, ∀r,t
Carbon = 0
```

如果后续数据或约束变化导致零碳不可行，则退回到：先求容量可行 `C_min`，再以 `[C_min, C_service]` 建立碳 ε 档位；不得预设 0%、50%、75%、100% 的比例。

## 3. REU 与弃电口径

| 项目 | 现行口径 | 拟改口径 |
|---|---|---|
| REU ε 终点 | 从基准 REU 线性推向 100% | 不再把 100% REU 设为目标；REU 作为零碳约束下的优化指标与展示指标 |
| 优化表达 | 最大化 REU | 等价地最小化弃电：`min Curtailment = ΣK_rt`；报告同时给出弃电 MWh 和 REU |
| REU 离散档位 | 每个碳预算下 `REU_Low/REU_MaxFound` 的 0/50/100% | 仅在端点搜索形成足够宽的可达区间时保留；若区间宽度小于 0.01 个百分点，则不再人为拆分档位，视作同一类方案 |
| 去重阈值 | 无 | REU 差异 < 0.01 个百分点且净成本差异 < 50,000 CNY 的方案视为同类，保留服务质量更优者 |

## 4. Pareto 轴改为服务等级 ε 轴

在零碳硬约束下，真正的冲突来自可再生消纳/售电收益与服务质量，而不是成本与碳排。因此拟使用加权等待作为主 ε 轴：

```text
WeightedWait = 2 × Σ Wait(BatchInference) + 1 × Σ Wait(AITraining)
WeightedWait ≤ W_j
```

其中 `W_j` 由以下两个端点自动生成：

- `W_min`：零碳条件下服务优先可行方案的加权等待；
- `W_max`：零碳条件下经济/弃电优先方案的加权等待；
- 三个服务等级：`W_min`、`W_min + 0.5(W_max-W_min)`、`W_max`。

每个服务等级内按以下层级求解并输出：

1. 硬约束：零碳、GPU/功率/网络/截止时间、`WeightedWait ≤ W_j`；
2. 主目标：净成本最小；
3. 次目标：弃电量最小（REU 最大）；
4. 平局打破：平均网络时延最小、迁移率最小。

迁移率不单独设 ε 轴，保留为平局打破和业务风险指标；若后续需要严格限制迁移，可增加 `MigrationRate ≤ M_max` 作为可选业务约束。

## 5. 成本与服务质量的报告口径

- `Cost_CNY` 固定解释为“购电成本减售电收益”的净成本；数值为负表示净售电收益，不能表述为负能耗或负电费。
- 每个推荐方案必须同时报告：净成本、购电 MWh、碳排 tCO2、售电 MWh、弃电 MWh、REU、平均等待、加权等待、平均时延、迁移率和最大 GPU 利用率。
- 所有增量指标以零碳服务基准为准；原始不可行业务对照仅放在单独的“调度必要性”表格中。

## 6. 结果筛选与验收

最终报告不再直接展示全部严格非支配点。先按上述去重阈值合并近似同类方案，再至少保留：

1. 服务优先零碳方案；
2. 平衡方案；
3. 经济/弃电优先零碳方案。

每个保留方案必须满足：

```text
Carbon = 0
所有硬约束检查为 PASS
WeightedWait ≤ 对应服务等级上限
```

若无法形成三档不同方案，应如实报告为“在给定数据下，零碳服务—经济前沿退化为少数方案”，不得通过随机种子或极小指标差异人为扩充 Pareto 点。
