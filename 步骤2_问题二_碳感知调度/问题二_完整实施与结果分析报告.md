# 问题二：碳感知调度完整实施与结果分析报告

## 1. 目标、数据范围与统一口径

问题二在**无储能**条件下，对跨区域 AI 任务的执行区域和开工时刻进行调度，目标是在满足业务服务质量和数据中心物理约束的前提下，分析成本、碳排放、可再生能源利用与任务服务质量之间的关系。

本实现使用步骤 0 清洗后的 `fact_tasks.csv`、`task_hour_profile.csv`、`task_region_eligibility.csv`、`fact_region_hour_input.csv`、`dim_region.csv` 和 `dim_storage.csv`。调度对象为 50,000 个任务，任务到达时刻为 0–2399，结算/结束边界为第 2406 小时。

统一采用以下口径：

- 实时推理任务必须在到达时刻启动；批推理和训练任务可在 `[EarliestStartHour, LatestFinishHour]` 窗口内延后，全部任务均不可抢占。
- 任务只能分配到网络时延不超过其 `MaxLatency_ms` 的区域。
- GPU、IT 功率、设施功率、购电上限、售电上限、最晚结束时刻和结算边界均是逐区域、逐小时硬约束。
- 不建立储能充/放电、SOC 或寿命决策；可再生能源不能跨时段转移。
- 每个区域—时段按“可再生本地直供—电网购电—余电售出—剩余弃电”结算。

对区域 `r`、时段 `t`，令 AI IT 负荷为 `a_rt`，非 AI IT 负荷为 `n_rt`，PUE 为 `p_r`，可再生可用功率为 `A_rt`。则：

```text
L_rt = p_r (n_rt + a_rt)                         # 设施侧负荷
D_rt = min(L_rt, A_rt)                            # 可再生直供
G_rt = max(L_rt - A_rt, 0)                        # 电网购电
S_rt = min(max(A_rt - D_rt, 0), ExportCap_rt)     # 售电
K_rt = A_rt - D_rt - S_rt                          # 弃电
```

指标定义：

```text
Cost = Σ (Price_rt × G_rt - SellPrice_rt × S_rt)
Carbon = Σ CarbonIntensity_rt × G_rt
REU = Σ(D_rt + S_rt) / ΣA_rt = 1 - ΣK_rt / ΣA_rt
```

因此在无储能、可再生能源总量给定时，最大化 REU 与最小化弃电量完全等价。

## 2. 参考方案与关键假设

### 2.1 原始业务对照

原始对照定义为“任务留在源区域、到达即启动、无储能”。该方案用于保留题目业务口径，但**不是可行调度解**：GPU 峰值超容量 358.8 张卡。其余 IT 功率、设施功率、电网、时延和截止时间检查通过。

原始对照指标：

| 指标 | 数值 |
|---|---:|
| 净成本 | -419,693,592.94 CNY |
| 碳排放 | 8.8506 tCO2 |
| 电网购电 | 31.5979 MWh |
| REU | 67.9164% |
| 弃电 | 3,704,067.85 MWh |
| GPU 最大违约 | 358.8 张卡 |

因此它不得进入 Pareto 集，也不得定义可行 ε 约束。

### 2.2 建模假设

- 功率与能量时间粒度均为 1 小时，MW 与单小时 MWh 数值等价。
- 调度仅改变任务执行区域和开始时刻，不改变任务 GPU 剖面、IT 能耗剖面和持续时长。
- 迁移不产生额外计算能耗；迁移代价通过网络时延、迁移率和服务指标反映。
- 净成本允许为负，负值表示售电收入高于购电成本。
- 售电计入 REU，因此 REU 的提升只来自减少弃电，而不是单纯增加可再生发电量。

## 3. 任务级数学模型

令任务集合为 `i ∈ I`，候选执行区域为 `r ∈ R_i`，候选开工时刻为 `s ∈ S_ir`。二元变量：

```text
x_irs = 1：任务 i 在区域 r、时刻 s 开始执行；否则为 0。
```

每个任务仅选择一个位置：

```text
Σ_(r∈R_i) Σ_(s∈S_ir) x_irs = 1,  ∀i
```

实时推理任务固定为 `s = ArrivalHour_i`。批推理和训练的候选时刻必须满足最早开始、最晚结束及结算边界。

由 `task_hour_profile` 给出的相对小时 GPU 剖面 `g_iq`、AI IT 功率剖面 `e_iq` 聚合得到：

```text
GPUUsed_rt = Σ_i Σ_s g_i,t-s × x_irs ≤ AvailableGPU_rt
NonAI_rt + AIIT_rt ≤ MaxITPower_rt
PUE_r × (NonAI_rt + AIIT_rt) ≤ MaxFacilityPower_rt
```

网络、购售电与服务约束分别为：

```text
Latency_(Source_i,r) ≤ MaxLatency_i
G_rt ≤ MaxGridImport_rt
S_rt ≤ MaxGridExport_rt
Finish_i ≤ LatestFinish_i,  Finish_i ≤ 2406
```

最终 Pareto 比较使用：净成本最小、碳排最小、REU 最大、加权等待最小、平均时延最小和迁移率最小。等待权重固定为批推理:训练 = 2:1。

## 4. 已实施的求解方案演进

### 4.1 第一版：固定 ε 网格的候选贪心

第一版以容量可行贪心排程为基础，固定设置碳预算比例 `[1.0, 0.75, 0.5, 0.0]`，并将 REU 从基准线性推向 100%。任务使用窗口端点、分位点及各区域能源优先级前若干时点作为候选，随后按边际成本、碳排、REU、等待与时延进行贪心选择。

该版本全部物理约束通过，但只有一个场景同时满足固定 ε 约束。原因不是容量，而是 REU 目标设置不可达：例如从 68.8482%提升到 84.4241%需要额外约 179.8 万 MWh 的可再生消纳，而所有 AI 任务设施侧能耗理论上限约 102.0 万 MWh。

第一版容量可行基准的结果为：碳排 41.9876 tCO2、REU 68.8482%、净成本 -445,214,643.60 CNY、平均等待 1.414 小时、平均时延 10.207 ms、迁移率 12.524%。

结论是：以“REU 达到 100%”定义 ε 终点不符合该数据规模，不能把未满足视作调度算法失败。

### 4.2 当前版本：两层自适应 ε-约束搜索

当前脚本 `run_q2_scheduler.py` 实现了以下两层框架：

1. **连续能源主问题（LP）**
   - 变量为区域—时段 AI IT 负荷、可再生直供、电网购电、售电和弃电；
   - 满足无储能逐时平衡、IT/设施余量、购售电上限和总 AI IT 能量守恒；
   - 分别求成本、碳排和弃电方向的连续目标负荷，作为任务级候选的区域—时段引导信号；
   - 主问题不直接作为最终方案，GPU 与任务剖面可行性由下一层严格处理。

2. **任务级可行构造和增量修复**
   - 每项任务的常规候选由最早/最晚时刻、窗口分位点和每个可行区域能源目标排名前 10 个时点组成；
   - 若某个峰值任务的常规候选全部不可行，仅对该任务展开完整合法时间窗，避免无界扩张候选集；
   - 成本方向优先尝试 LP 引导构造。若出现早期任务集中导致后续任务无位置的贪心死锁，则自动回退至已验证的容量可行构造；
   - 碳排和弃电方向直接从容量可行种子出发，再通过 LP 引导的单任务迁移、移时和双任务交换修复；
   - 每次试探仅对受影响的区域—时段增量重算成本、碳排、REU、GPU 和功率约束，不接受任何物理约束违例；
   - 默认进行 25,000 次单任务迁移尝试和 10,000 次双任务交换尝试，随机种子固定为 `20260808`。

3. **自适应 ε 定义**
   - 先搜索成本可行端点 `C_base` 与最低碳端点 `C_min`；
   - 在 `[C_min, C_base]` 内生成四个碳预算；
   - 对每个碳预算，从已找到的容量可行候选中记录 `REU_Low` 与 `REU_MaxFound`；
   - 以 `REU_Low + q(REU_MaxFound-REU_Low)` 生成 `q=0,0.5,1` 的三个 REU 下限；
   - 只有物理约束、碳预算和 REU 下限均通过的解才进入 Pareto 筛选。

## 5. 当前版本的运行结果

### 5.1 可行性

本轮 12 个场景全部完成，12/12 通过 GPU、IT 功率、设施功率、购售电、实时启动、网络时延、最晚结束和结算边界检查；12/12 也满足脚本生成的 ε 约束。

|---|---:|---:|---:|---:|---:|---:|---:|
| 容量可行成本基准 | -445,206,078.07 | 0.0000 | 68.8477% | 3,596,552.13 | 1.4398 | 10.1992 | 12.52% |

### 5.2 结果的关键结构性发现

成本基准已经实现零购电、零碳排，因此：

```text
C_base = C_min = 0
```

四个自动碳预算均为 0 tCO2。也就是说，在当前数据与允许的迁移/延后范围内，零碳和净成本改善是同向的，碳排不再构成成本的对立维度。此结论来自数据和无储能结算口径，不是约束检查失效。

相应地，四个“碳层级”均为零碳层级；每一层中 `REU_Low = REU_MaxFound`，0/50/100% REU 标签没有构造出真正不同的 ε 区间。12 个方案虽全部可行，但不能解读为完整的四档成本—碳排 Pareto 前沿。

三者均为 0 tCO2、0 MWh 购电。净成本最佳方案相对成本基准改善约 752.9 万 CNY，但平均等待从 1.44 小时增加到 11.87 小时，迁移率从 12.52%增加到 43.86%。服务优先方案牺牲约 142.8 万 CNY 的净收益，以显著降低时延和迁移率。

## 6. 结果解读与当前局限

### 可直接采用的结论

- 在本数据及约束下，存在满足全部硬约束的零购电、零碳排调度方案。
- 原始源区域即时方案的低碳指标没有决策意义，因为其 GPU 不可行；应以容量可行方案为比较起点。
- 零碳的主要业务代价不是电费，而是训练/批任务的等待、跨区迁移和网络时延。
- 由于售电收入显著，零碳方案还可能取得更低的净成本；报告成本时应说明其为“购电成本减售电收益”。

### 尚不能直接作为最终竞赛结论的部分

- 当前碳 ε 轴退化为零，不能声称已经获得成本—碳排完整 Pareto 前沿。
- 当前每层 REU 端点区间退化，0/50/100% REU 标签主要反映局部搜索路径，而非有显著业务差异的三档可再生利用目标。
- 11 个方案被判为非支配，主要是将成本、REU、等待、时延和迁移率同时纳入严格非支配判定；其中部分数值差异很小，不应全部作为独立推荐方案。
- 连续能源主问题用于引导而非精确任务分配；最终结果是可复核的启发式解，不是全局 MILP 最优性证明。

## 7. 建议的后续定稿口径

若继续优化问题二，建议保持“零购电/零碳”为硬约束，并将原先退化的碳 ε 轴替换为服务等级 ε 轴：

```text
Carbon = 0（硬约束）
WeightedWait ≤ W_j 或 MigrationRate ≤ M_j（服务等级约束）
在该约束下：先最小化净成本，再最小化弃电/最大化 REU。
```

建议服务等级按容量可行成本基准和零碳收益端点之间的等待或迁移范围设置三档，并加入结果去重阈值。例如 REU 差异小于 0.01 个百分点且净成本差异小于 5 万 CNY 的方案视为同类，仅保留等待、时延和迁移率更优者。

这样可将问题二的最终叙事统一为：**在保证零碳的前提下，量化可再生利用和售电收益提升所需付出的服务质量代价，并给出不同服务等级下的可执行调度方案。**

## 8. 复现、参数与输出

运行命令：

```powershell
python .\步骤2_问题二_碳感知调度\run_q2_scheduler.py
```

主要参数位于 `q2_config.json`：四个碳层级、REU 比例 `[0, 0.5, 1]`、每区域 10 个能源候选时点、迁移尝试 25,000 次、交换尝试 10,000 次和固定随机种子。

本轮生成的关键文件：

- `reference_metrics.csv`、`source_immediate_constraint_checks.csv`：原始业务对照；
- `feasible_baseline_metrics.csv`：容量可行成本基准和碳端点；
- `endpoint_bounds.csv`：各碳预算及 REU 搜索区间；
- `scenario_epsilon_definition.csv`：12 个场景的绝对 ε 定义；
- `scenario_summary.csv`、`pareto_solutions.csv`：全部场景汇总；
- `constraint_checks_all_scenarios.csv`：全部场景硬约束检查；
- `task_schedule_*.csv`、`region_hour_*.csv`：逐任务和逐时排程明细；
- `q2_report.md`：程序自动生成的简版运行报告。
