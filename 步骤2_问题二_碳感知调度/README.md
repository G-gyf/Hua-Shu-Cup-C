# 问题二：数据驱动 ε-约束碳感知调度

本目录实现无储能条件下的跨区域任务迁移与开工时间调度。输入来自步骤 0 的 `processed` 数据，脚本不修改任何输入数据。

## 统一口径

- 调度 50,000 个任务，任务到达范围为 0–2399，结算边界为第 2406 小时。
- 实时推理必须到达即启动；批推理与训练可等待，任务均不可抢占。
- GPU、IT 功率、设施功率、购电/售电上限、网络 SLA、最晚结束均为逐时硬约束。
- 无储能：可再生能源依次用于本地直供、余电售出与弃电；碳排只计电网购电；REU 等价于 `1 - 弃电量 / 可再生可用量`。
- “源区域、到达即启动”方案保留为业务对照，但其 GPU 峰值超容量，绝不作为可行解、ε 基准或 Pareto 点。

## 求解流程

1. 能源主问题使用线性规划，在无储能平衡、逐时功率余量和购售电限制下生成区域—时段 AI IT 负荷目标；分别求成本、碳排和弃电方向的连续端点。
2. 任务层从空负载构造容量可行排程。常规候选为窗口边界、分位点和每个可行区域能源目标排名靠前的时点；峰值任务若无候选，则仅对该任务展开完整合法时间窗。
3. 成本方向优先使用 LP 引导构造；碳/弃电方向以已验证的容量可行种子开始，再由 LP 目标引导迁移和交换修复，避免贪心集中到同一峰值时段造成死锁。
4. 先搜索实际碳端点 `C_base` 与 `C_min`，在该可达区间生成四档碳预算。对每个碳预算，先求已找到的 `REU_Low` 与 `REU_MaxFound`，再在该区间取 0/50/100% 三档 REU 下限。
5. 每个最终场景执行增量迁移和成对交换。修复优先级为碳预算、REU 下限、净成本、加权等待时间、网络时延和迁移率；所有结果均由任务级排程重新计算并严格核验。

这一定义保证 REU 目标来自该碳预算下已搜索到的可达区间，不会再出现把 84% 或 100% REU 误设为必达目标的情况。

## 运行

在仓库根目录执行：

```powershell
python .\步骤2_问题二_碳感知调度\run_q2_scheduler.py
```

运行会删除并重建 `调度结果`。默认包含 4 个自适应碳档位 × 3 个 REU 档位、两类初解和局部修复；预计 **2–4 小时**。

## 输出

- `reference_metrics.csv`、`source_immediate_constraint_checks.csv`：原始业务对照及其容量违约；
- `feasible_baseline_metrics.csv`：成本可行基准与碳端点；
- `endpoint_bounds.csv`：每个碳预算的绝对预算、`REU_Low` 与 `REU_MaxFound`；
- `scenario_epsilon_definition.csv`：12 个最终场景的绝对 ε 约束；
- `scenario_summary.csv` / `pareto_solutions.csv`：成本、碳排、REU、弃电、等待、时延、迁移和非支配标记；
- `constraint_checks_all_scenarios.csv`：全部场景的硬约束核验；
- 每个 ε 可行场景的 `task_schedule_*.csv`、`region_hour_*.csv` 与 `constraint_checks_*.csv`；
- `q2_report.md` 与 `figures/pareto_cost_carbon.png`：自动汇总报告和图。
